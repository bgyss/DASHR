# Upstream future work and limitations: fork traceability

Source: the "Limitations and subtleties" and "Future work" sections of Tom Forsyth's [published paper](../../paper/DASHR_Paper.html#future-work) (v1.0, 2026-09-27; README/publication update 2026-09-29, merged 2026-09-30). The paper remains the algorithm authority. This page restates each of Tom's points, says how this fork treats it and links the workstream that owns it. Status values: **Open** (no work), **Planned** (owned by a workstream), **Partial** (some implementation exists, acceptance incomplete), **Fork decision** (this fork deliberately differs from upstream scope).

All expected benefits are hypotheses until measured under the [benchmark protocol](../research/2026-09-29/benchmark-protocol.md). Tom's paper describes the project as a research paper and proof of concept, says he is not seeking pull requests and explicitly invites others to turn it into a real library. This fork takes up that invitation; see [standalone library and integrations](standalone-library-and-integrations.md). Preserve attribution (see [provenance](../port/provenance.md)) and keep fork-specific claims separate from upstream's.

## Tom's "Reasonable, but low-priority" items

| ID | Tom's point | Fork status and owner |
| --- | --- | --- |
| U7 | Store inverse `surfaceFromObject` from the distortion pass in a separate texture instead of inverting at shading | Partial: five alternating 120-warm/300-measured A/B runs show only 0.8% lower trace median, while total GPU median rises 4.35% and p95 rises 8.60%; the cube probe also has max RGB error `0.0036595762` and the design adds 75% atlas payload. Evidence supports no-go for default promotion; U7 remains open pending approval of that disposition. See [U7 experiment](../port/validation.md#u7-stored-inverse-atlas-experiment) |
| U8 | Edgefill copy as a compute shader with read/write target, only copying needed regions (Animation Distortion still needed for the whole mesh) | Partial: the full-atlas compute path matches raster maps within `4.76837e-7` across three `TubePinched` poses and zeroes status/RGB differences. Five-run bent-fixture timing lowers edgefill median `76.4%` and total GPU median `8.9%`; selective writes still lack a conservative reachable-UV bound. A no-go for selective writes while retaining full-atlas compute is proposed, pending approval (see [U8 experiment](../port/validation.md#u8-compute-edgefill-prototype)) |
| U9 | Replace the edgefill copy with mesh "fins" written in the first pass | Closed no-go for the current portable library: pinned wgpu 30.0.1 classic rendering has no geometry stage, CPU-expanded fins need exporter-level seam adjacency and matching skinning/atlas coverage, and the measured U8 full-atlas compute path already lowers bent-fixture edgefill time 76.4% with exact output. Revisit only with schema support and a matched prototype that proves an additional benefit (see [U9 decision](../port/validation.md#u9-mesh-fin-alternative-decision)) |
| U10 | Have `TraceRay` always indirect through the Edgefill Texture (filtered read, finite-difference distortion) | Partial: the refreshed cube probe preserved all `5,120` primary status/hit samples and added no budget/invalid exits, with max RGB error `0.003795326`. Five-run medians show trace time +14.1% and total GPU time +4.9%, with a high first-run timestamp outlier; a no-go for default promotion is proposed, pending approval. Curved/seam fixtures and other adapters remain unmeasured (see [U10 experiment](../port/validation.md#u10-trace-time-edgefill-indirection-experiment)) |
| U11 | Two-channel teleport SDF to recreate sharp corners between two edges | Closed no-go for the initial library: `Maps::teleport` holds one signed distance and one destination per texel, with no stable seam ID, so corner combination and destination semantics are undefined. Revisit only with an analytic corner fixture and a documented tie/combination rule (see [U11/U13 decision](../port/validation.md#u11u13-multi-seam-representation-decision)) |
| U12 | Split the teleport SDF (single channel, read every step) from the 2-channel destination (read only on teleport) | Closed for the native storage-layout scope: R32F distance plus RG32F destination exactly reproduce the packed map/frame and reduce seam-map payload 25%. Five-run cube timing is neutral (`0.811500` vs `0.811001 ms` total GPU median); retain as an opt-in memory tradeoff pending curved-seam/other-adapter review (see [U12 experiment](../port/validation.md#u12-split-teleport-distance-and-destination)) |
| U13 | Multiple teleport textures so discontinuities are separated and each can be bilinearly filtered, fewer iterations after teleporting | Closed no-go for the initial library: `Maps`/`AssetDocument` do not preserve seam-group IDs, so filtered destinations could blend across discontinuities and violate the nearest-destination contract. Revisit with a versioned seam-group schema and a per-group destination fixture (see [U11/U13 decision](../port/validation.md#u11u13-multi-seam-representation-decision)) |
| U14 | Replace float32 texture/vertex storage with compact formats | Partial: the opt-in RGBA16F raw/warp atlas halves storage and preserves cube statuses, but the bent `TubePinched` fixture changes four primary and ten shadow statuses with max RGB error `0.3348779`. A no-go for default promotion of this format is proposed, pending approval; vertices and seam maps remain full precision (see [U14 experiment](../port/validation.md#u14-compact-transform-atlas)) |
| U15 | More efficient maths, e.g. 4x3/3x3 inverse instead of a general 4x4; confirm compiler behavior | Closed no-go for default promotion, approved 2026-10-03: the opt-in 3x3 cofactor inverse matches CPU/flat-GPU oracles and has zero cube status differences with max RGB error `5.96046e-8`, but five-run median trace improvement is only 0.82% and total GPU median is 0.21% slower. Actual Windows/FXC compilation and another adapter remain open (see [U15 experiment](../port/validation.md#u15-specialized-inverse-experiment)) |

## Tom's "Out of scope for my work" (fork position)

| ID | Tom's point | Fork position |
| --- | --- | --- |
| U16 | T-junctions, interpenetrating triangles, self-intersecting meshes, arbitrary triangle soup | Native rejection path verified: `AssetDocument::validate_pose_topology` rejects T-junctions and posed crossings with vertex/face/chart IDs, reports coplanar overlap and ordinary contacts correctly, and rejects open edges plus indexed edges incident to more than two faces with stable IDs before map baking. Lone-edge/thin-sheet support is proposed for deferral to P13: schema v1 lacks cliff-edge data, the paper notes surface-space ambiguity, and P13 explicitly says to stop rather than ship partial mapping if open edges require a different definition. Approval is pending (see [U16 topology contract](../port/validation.md#u16-supported-topology-contract)) |
| U17 | Acceleration structures (min-max mips, horizon maps), better lighting, AO, SSS | Closed no-go for production acceleration in the native library under the accepted plan: conservative height bounds are unproved across deformation, gutters and teleports. The public Rust output carries actual hit depth and distinct local-shadow statuses; a rerun of the Metal public-library probe exercised them on a bent, seam-remapped `CubePinched` frame with zero budget/invalid exits. AO, SSS and long-range visibility remain host responsibilities (see [U17 validation](../port/validation.md#u17-conservative-bounds-and-host-lighting-boundary)); target-engine integration remains open |
| U18 | A general robust drop-in library | Closed for the native standalone Rust library contract: the default headless crate, v1 asset/cache formats, documented lifecycle/version/thread/device rules, independent locked Rust consumer, and optional C ABI v1 smoke all pass on Apple M1 Max / Metal. Engine-owned GPU resources, target engine shader compilers/scenes, Blender/Unity/Unreal integration, broad import and P13 topology extensions remain open; see the [U18 validation](../port/validation.md#u18-standalone-rust-library-closeout) and [library plan](standalone-library-and-integrations.md) |
| U19 | Non-heightfield representations (SDF, fractal, splats, voxels) | Closed for bounded feasibility/recommendation scope under accepted Task 8; no candidate is promoted to the production surface library. The [research note](../research/2026-10-03/non-heightfield-warps-u19-u20.md) records analytic SDF/warp probes, CPU voxel bounds, 32³/64³ inverse-LBS voxel probes, finite Menger depth-2 timing and depth-3/4 correctness, and a GPU-sorted Gaussian adapter. Depth 2/3 match exact CPU references; depth 4 has 400 exact hits and four exact misses preserved as budget exits. Gaussian sorting/compositing matches the CPU adapter, but silhouette IoU remains `0.541` and its depth is not a unique surface hit. Broader fractal families, authored splats, full-frame human review and production adapters remain open promotion gates; variable timing samples are not adoption evidence |
| U20 | Animating characters in other representations by warping spaces on GPU | Closed for bounded native feasibility research: the [two-bone inverse-LBS probe](../research/2026-10-03/non-heightfield-warps-u19-u20.md#two-bone-inverse-lbs-feasibility-probe-2026-10-03) and voxel warp use CPU double-root truth, a 120-pose sequence, a forward-skinned mesh baseline and an actual π-radian self-intersection pose. The current Metal tests pass: 3,840 analytic/voxel statuses match CPU with zero inverse failures or conservative-step violations; 64³ lowers max analytic hit error from `0.016367` to `0.003553` at 8× payload; the self-intersection pose returns `Invalid` for all 32 rays. No production warp mode is promoted. Full-frame silhouette/normal/temporal review and engine integration remain open promotion gates |

## Tom's "Limitations and subtleties"

| ID | Limitation | Fork handling |
| --- | --- | --- |
| L1 | Requirements: unique UV map, sufficient gutter, no T-junctions, consistent UV winding (could be relaxed), every edge shared by exactly two triangles (possibly across a seam) | The exporter enforces the authored input contract, and the library's `validate_pose_topology` preflight checks seam-pairable closed geometry before baking; `AssetDocument::validate` alone remains structural. Winding relaxation and open edges are L2 |
| L2 | Sharp/lone edges need extra "cliff edge" geometry, needed for clothing; Tom plans to work on this | Planned: P13 topology extensions (cliff-edge geometry, open boundaries, thin sheets). Design after the closed-mesh library milestone; do not combine with initial port parity |
| L3 | Smooth displacement normals required across seams; a smarter mesh preprocessor could fix this. Sharp surface normals can live in heightfield/normal maps | Planned: exporter/preprocessor (P5 and P13). Report discontinuities per vertex; a forced seam plus teleport is the recommended remedy |
| L4 | Tangent/bitangent lengths matter; MikkTSpace normalises and is unsuitable without modification | Already a fork contract (metric tangent lengths). Planned: a DASHR-specific metric tangent generator in the library, with a documented MikkTSpace-compatible export option for engine shading only |
| L5 | Tangent discontinuities cause extra iterations and tornado poles; prefer forced seams plus teleports | Diagnostics in the importer (see U1) |
| L6 | Self-intersecting bent surfaces produce tunnels | See U5 |
| L7 | The demo is not a benchmark; compact formats, shader variants and context-specific tuning needed | Fork's [benchmark protocol](../research/2026-09-29/benchmark-protocol.md); no speedup claims from GUI FPS. Production shader variants per engine target |
| L8 | The raymarcher is unsophisticated; no min/max mips or horizon maps | See U17 |
| L9 | Self-shadowing stops outside the local skin volume; combine with shadow buffers for long range. Local raymarched shadows let shadow-buffer epsilons relax | Library plan: the host engine owns long-range shadows. Document the hand-off (DASHR supplies local shadow term and actual hit depth). Inter-object shadows are a named gap |
| L10 | One UV set currently drives albedo, normal, height and tangent space; separate, non-unique material UVs are possible but error-prone | Planned: schema revision after the unique-atlas milestone. Name each UV/tangent space in code and schema so mixing is visible |
| L11 | Seams need artists to match albedo/heightfield on both sides; robust solutions should be investigated | Planned: seam-continuity checks in the exporter plus an optional seam-blend/bake assist (P13). Height mismatch measured at teleports, per U2 |
