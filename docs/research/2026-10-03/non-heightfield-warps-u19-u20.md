# U19-U20: Non-heightfield representations and GPU space warps

Research note, 2026-10-03. This report expands the isolated U19/O8 and U20/R4 tracks in the [future-work register](../../plans/upstream-future-work.md), [optimization workstreams](../2026-09-29/optimization-workstreams.md#o8-research-beyond-heightfields), and [library plan](../../plans/standalone-library-and-integrations.md#research-tracks). U19 and U20 are closed for their bounded feasibility/recommendation scopes: analytic SDF, finite Menger, Gaussian adapter, dense voxel and inverse-LBS warp probes have explicit decisions, and none is promoted as a general production-library representation under the accepted Task 8 contract. Authored assets, full-frame human review, broader families and production adapters remain promotion gates. The cited methods show prior art; the measured results are DASHR-specific and make no general speed claim.

## Recommendation at a glance

| Candidate | Isolated prototype | Recommendation for DASHR | Main gate before any promotion |
| --- | --- | --- | --- |
| Signed distance field (SDF) | Small analytic field inside one existing chart/shell, then one articulated warp | **Go** for a bounded correctness prototype; **no-go** as a general library representation today | Prove conservative step bounds after deformation and report folds or failed inverse queries |
| Procedural fractal field | Finite depth-2 Menger sponge as a union of 400 axis-aligned boxes, queried by exact flat scan and median-split BVH | **Go** for this bounded correctness and acceleration probe; **no-go** for generic Mandelbulb-style estimators without a lower-bound proof | Measure build/storage and query cost at greater Menger depth or image size; prove bounds independently for other fractal families |
| 3D Gaussian splats | A deterministic capsule sample with anisotropic covariance, two-bone update, and front-to-back compositing | **Go** as a separate rendering-adapter experiment; **no-go** as a drop-in surface/ray-hit field | Improve matched-mesh coverage/depth, test an authored splat asset, and define scene occlusion/sorting |
| Voxels | Dense 32³ and 64³ signed-distance grids for one bounded capsule under the same two-bone pose sequence | **Go** for a bounded dense SDF prototype; **no-go** on sparse streaming in the first pass | Review full-frame silhouettes and normals, then decide whether the memory increase buys enough image-space quality |

U20 should first answer one constrained question: can a specified two-bone warp move a canonical SDF while maintaining conservative tracing and stable normals? Start with a query-to-canonical map whose inverse and stretch bound are known; evaluate inverse linear-blend skinning as a separate, explicitly counted variant. A learned deformation model would confound the geometry question. If that gate passes, reuse the same pose sequence and warp contract for a voxel field. Gaussian avatars already provide close prior art for skinning splats, so their DASHR experiment should test interoperability and output semantics rather than claim a new general warp method.

## Representation boundaries

The word “field” covers data with different rendering semantics. A scalar SDF or voxelized occupancy may define a surface hit; a volume may instead accumulate opacity/color along the ray; 3D Gaussian splatting represents and composites anisotropic radiance primitives. The original 3DGS method uses anisotropic 3D Gaussians and a visibility-aware splatting renderer for radiance-field views ([Kerbl et al., 2023](https://doi.org/10.1145/3592433)). It therefore does not provide the same unique zero crossing, surface UV, or hit-depth contract as an opaque scalar surface. That distinction is a design inference from the cited representation and renderer and must remain explicit in any adapter.

Likewise, a voxel grid is a storage family, not a single surface definition: volume-rendering work such as GigaVoxels treats voxel data as general volumetric content, so this report makes sample semantics an explicit design choice ([Crassin et al., 2009](https://www-sop.inria.fr/reves/Basilic/2009/CNLE09/CNLE09.pdf)). The first prototype should choose exactly one: binary occupancy, signed distance, density, or color/opacity. This report recommends an SDF-valued grid for the trace comparison, so its hit and step behavior can be compared to the analytic SDF; it does not recommend implementing a general volume renderer.

## U19 candidate assessments

### SDF: bounded go

Hart’s sphere-tracing formulation advances a ray using a conservative distance to an implicit surface, avoiding steps through the surface when the query is a valid distance bound ([Hart, 1996](https://doi.org/10.1007/s003710050084)). This is the closest U19 candidate to DASHR’s existing ray-query path: both can return a geometric hit, while an SDF supplies a volumetric scalar query instead of chart-local height.

**Prototype question.** Within one well-conditioned chart and the existing reference shell/seam wrapper, can an analytic capsule or rounded-box SDF replace the height lookup without changing the shell and pose? Then apply a two-bone bend and compare an undeformed reference field, a deformed mesh oracle, and the warped field. Start with smooth closed geometry, not clothing, thin sheets, or arbitrary intersections.

**Warp assumption.** For an exterior query, if the canonical field is a conservative signed-distance lower bound `d` and a query-space warp `W` has a known global Lipschitz upper bound `L`, then `d(W(x)) / L` is a conservative object-space step bound. This is a first-principles design derivation from the distance-bound requirement, not a DASHR result. A local Jacobian estimate alone is not a global guarantee; folds, singular bases, and unbounded stretch can invalidate it. Keep a safe fallback (smaller step or explicit failure status), not a hidden iteration cap.

**Baseline and measures.** Compare against a high-resolution skinned mesh and the same analytic SDF without deformation. Record silhouette/hit-mask disagreement, projected hit-position and depth error, normal angular error, maximum and percentile trace steps, invalid/failed warp queries, visible folds, and GPU time for warp and trace separately. Freeze thresholds before the run using the repository’s [benchmark protocol](../2026-09-29/benchmark-protocol.md); report the full pose sequence and worst seam/silhouette regions, not only image averages.

**Failure modes / decision.** A warped SDF ceases to be an exact Euclidean distance in posed space; conservative bounds need a deformation bound. Backward maps may be non-unique at folds, and finite-difference normals amplify field discretization and warp distortion. Proceed only as an isolated prototype; do not expose SDF as a stable library asset type until bounds, transform conditioning, and failure statuses are specified.

### Procedural fractal: finite Menger hierarchy, generic estimator deferred

Hart, Sandin, and Kauffman show ray tracing deterministic 3D fractals using an “unbounding volume” construction ([Hart et al., 1989](https://www2.evl.uic.edu/documents/raytracing3d.pdf)). This establishes a rendering route for particular procedural fractals; it does not make every popular fractal distance estimator safe for sphere tracing or animation.

**Bounded prototype.** A depth-2 Menger sponge is represented as the union of the 400 sub-cubes retained by two recursive levels of the 3×3×3 construction. The flat GPU baseline evaluates the minimum exact box SDF for each query. The follow-up builds a median-split BVH with at most four boxes per leaf; point-to-node-AABB distance is a lower bound, and exact box SDFs at leaves define the field. The CPU reference intersects the same boxes analytically along deterministic orthographic rays and also compares hierarchical and flat distances on a 9³ query grid.

**Measured result.** On Apple M1 Max / Metal, the 256 rays produced 116 hits. GPU and CPU statuses matched exactly; maximum/median hit-distance error was `0`, and no conservative step violations occurred. Trace steps were p50/p95/max `16/137/137`. The probe used two warm-up and ten measured dispatches; median/p95 compute time was `7.750458/7.750834 ms`. The flat box list occupies `6,400` bytes. This is a small compute feasibility result, not a screen renderer or a performance comparison against DASHR.

**Hierarchical follow-up (2026-10-03).** The median-split tree contains 255 nodes and stores 12,240 bytes, in addition to the 6,400-byte box payload. Ten measured CPU builds after two warm-ups took median/p95 `0.030041/0.032042 ms`. On a 9³ CPU query grid, the maximum distance difference from the flat union was zero; the hierarchy evaluated an average of `5.838` box SDFs and visited `17.479` nodes per point. A matched 32×32 GPU run compared flat and hierarchical tracing on the same 1,024 rays. Both paths matched the exact CPU ray-box statuses, with zero conservative-step violations and zero hit-distance error; the BVH had zero stack overflows. The flat scan evaluated 400 box SDFs per distance query; the hierarchy averaged `6.009` box evaluations and `17.498` node visits. One stored aggregate reports flat median/p95 compute time `3.875417/3.890000 ms` and hierarchical `1.314709/1.320208 ms`; an earlier run recorded `3.923125/4.793625` and `1.320459/1.323542 ms`. Treat those as run-specific timings, not a general speed claim. The wider 32×32 sequence reported 552 hits. The raw reports are under `out/u19-bvh/capabilities.json` and `out/probe/capabilities.json`.

**Depth-three follow-up (2026-10-03).** The generator and WGSL query now accept a finite stage of depth 3: 8,000 exact sub-cubes in a 4,095-node median BVH. On a 9³ CPU query grid, the hierarchy matched the flat finite union with zero maximum distance error, averaging `8.439` box SDF evaluations and `30.147` node visits per point. On Apple M1 Max / Metal, 1,024 GPU rays matched exact CPU ray-box statuses and hit distances with 496 hits, zero status disagreements, zero conservative-step violations and zero stack overflows. The BVH averaged `8.622` box evaluations and `27.858` node visits per distance query; trace steps were p50/p95/max `14/69/131`. One CPU build took `1.116 ms`; no depth-three GPU dispatch timing was collected. The raw run is under `out/probe/capabilities.json`.

**Depth-four limit (2026-10-03).** At depth 4 the hierarchy contains 160,000 boxes and 123,391 nodes, using `2,560,000` bytes for boxes and `5,922,768` bytes for nodes. A 9³ CPU distance grid matched the flat union exactly. On M1 Max / Metal, 1,024 rays produced 400 exact box hits. All hit statuses and distances matched; the BVH had zero conservative-step violations and zero stack overflows. Four exact-miss rays near `(±0.5078, ±0.5078)` remained within a very small positive SDF distance and exhausted the 1,024-step budget, so those four results remain `Budget` rather than being mislabeled as escapes. No expected hit exhausted the budget. The maximum hit-distance error was zero; average BVH work was `7.381` box evaluations and `42.240` node visits per query. Trace steps were p50/p95/max `15/467/1024`. One CPU build took `33.475 ms`; no depth-four GPU timing was collected. The raw report includes the four ray diagnostics under `out/probe/capabilities.json`.

**Failure modes / decision.** This hierarchy evaluates finite unions only; it does not establish a distance estimator for other fractal families or an infinite Menger sponge. Depth 3 matches every ray; depth 4 exposes four grazing empty-channel rays that do not escape within 1,024 steps. Keep explicit budget status for those rays and retain the prototype outside DASHR's library API. Repeated depth-four build/query timing, another adapter, larger render workloads, further stages and general fractal bounds remain open. Hart et al. ray trace selected deterministic fractals with a dedicated unbounding-volume construction; that result does not validate an arbitrary Mandelbulb-style estimator ([Hart et al., 1989](https://www2.evl.uic.edu/documents/raytracing3d.pdf)).

### 3D Gaussian splats: separate adapter go

The original 3DGS paper represents scenes with anisotropic 3D Gaussians and renders them with a visibility-aware splatting algorithm ([Kerbl et al., 2023](https://arxiv.org/abs/2308.04079)). Character-specific work already combines Gaussian primitives with skeletal pose: HUGS initializes human Gaussians from SMPL and learns skinning weights, while discussing articulation artifacts ([Kocabas et al., CVPR 2024](https://openaccess.thecvf.com/content/CVPR2024/papers/Kocabas_HUGS_Human_Gaussian_Splats_CVPR_2024_paper.pdf)); GaussianAvatar uses forward skinning to repose canonical Gaussians and adds pose-conditioned appearance modeling ([Hu et al., CVPR 2024](https://openaccess.thecvf.com/content/CVPR2024/papers/Hu_GaussianAvatar_Towards_Realistic_Human_Avatar_Modeling_from_a_Single_Video_via_Animatable_3D_Gaussians_CVPR_2024_paper.pdf)). These are direct prior art for U20, but they are not evidence about DASHR’s renderer or its speed.

**Prototype question.** Can a host-independent DASHR adapter accept already-built canonical Gaussians plus fixed skinning weights, update their centers/orientations/scales on the GPU, and expose a stable color/coverage/depth hand-off for one character? Avoid training or reconstruction in the first pass. For locally affine deformation, transforming an anisotropic covariance by the warp Jacobian (`Σ' = J Σ Jᵀ`) is a candidate design to test, not a required implementation assumption.

**Baseline and measures.** Compare the splat output with the same character’s conventional skinned mesh at identical poses/camera/material intent. Report silhouette overlap, image-space color error, temporal flicker, depth/coverage mismatch, per-pose primitive count, warp/update time, sorting/compositing time, memory, and frame-to-frame changes. Do not treat a splat image as a geometry oracle; the comparison is for visual and integration behavior. If no suitable matched splat asset exists, stop at a procedural Gaussian test and label it an adapter prototype.

**Failure modes / decision.** Splat support needs alpha/compositing and visibility rules beyond an opaque scalar hit; a single “surface hit” may be ambiguous. Skinning can distort primitives or expose unseen appearance, and sorting/overlap can change image output. Proceed as a separate host-facing renderer experiment, not as a new DASHR surface representation. There is no reason to make this part of the core library until an explicit consumer requires splat outputs.

**Executed adapter probe (2026-10-03).** `src/probe/splat.rs` generates 256 anisotropic Gaussian samples from the canonical capsule. The GPU applies the two-bone LBS Jacobian to each covariance and center, sorts the 256 posed center depths per pose with a bitonic workgroup kernel, then front-to-back composites premultiplied color, coverage and opacity-weighted center depth into a 32×32 image at two poses. A CPU mirror checks both the sort order and composite, and the existing 1,488-triangle forward-skinned capsule supplies a coverage/depth reference.

On Apple M1 Max / Metal, the GPU produced the same sorted primitive indices as the CPU reference at both poses, with zero depth-order inversions. The sort-index buffer uses `2,048` bytes. CPU and GPU composite outputs agreed within `3.15e-7` color, `4.05e-7` coverage and `6.62e-6` depth, with zero pixels outside the `1e-3` output tolerance. The splat coverage mask included all 314 mesh-hit pixels but covered 266 additional pixels, for silhouette IoU `0.541` at a `0.5` coverage threshold. On common pixels, the opacity-weighted center-depth difference from mesh hits was median/max `0.02580/0.12684` object units. The current stored aggregate reports depth-sort median/p95 `0.028292/0.028625 ms` and compositing `0.229625/0.231042 ms`; an earlier run recorded `0.051834/0.052375` and `0.428291/0.430834 ms`. These are variable probe timings, not a speed comparison or promotion claim. The raw aggregate is under `out/probe/capabilities.json`.

This proves the isolated GPU skin/covariance/sort/compositing path and its output contract for a fixed 256 primitives. The current procedural splats over-cover the skinned mesh substantially, and their representative depth is not surface depth. An authored splat asset, denser/sparser coverage trade-offs, sort scaling beyond 256 primitives, visual review and host scene integration remain open; keep the adapter separate from the production surface API.

### Voxel field: dense bounded go

GigaVoxels combines an adaptive octree, voxel bricks, ray casting, and view-guided streaming to render large volumes. Its authors identify voxel storage and traversal costs and explicitly call animation a major open problem ([Crassin et al., 2009](https://www-sop.inria.fr/reves/Basilic/2009/CNLE09/CNLE09.pdf)). That paper supports sparse hierarchy as a mature rendering direction but also warns that animation is a separate hard problem; it does not justify starting DASHR with an animated sparse hierarchy.

**Prototype question.** What resolution of a dense SDF texture is enough for one bounded character segment under a two-bone bend, and can inverse pose warping retain acceptable hit, normal, and silhouette quality? Fix one small grid size and one asset; establish a density/resolution sweep before any sparse structure.

**Baseline and measures.** Compare a trilinearly sampled dense SDF with the analytic field used to generate it and a high-resolution skinned mesh. Record grid bytes, upload/update cost, warp plus field-sampling time, trace steps, hit-mask disagreement, depth and normal error by resolution, and temporal stability through compression/twist poses. For field storage, report the exact scalar definition and quantization; do not compare opacity accumulation to opaque-surface hits.

**Failure modes / decision.** Resolution limits thin features; interpolation can shift zero crossings and gradients, and trilinear samples do not automatically preserve the analytic field’s conservative step bound. Per-frame grid resampling can dominate the trace cost. A sparse octree adds traversal, LOD, residency, and update policy. GigaVoxels’ streaming and LOD mechanisms depend on view-guided management, while deforming content can invalidate spatial organization. Prototype dense and bounded first; consider sparsity only after memory is measured as the limiting cost.

## U20 GPU-space-warp track

Canonical/deformed-space mappings are established in dynamic neural rendering: D-NeRF represents a scene in canonical space and maps it to a time-dependent deformed scene ([Pumarola et al., CVPR 2021](https://openaccess.thecvf.com/content/CVPR2021/papers/Pumarola_D-NeRF_Neural_Radiance_Fields_for_Dynamic_Scenes_CVPR_2021_paper.pdf)). For articulated implicit shapes, SNARF finds canonical correspondences for posed points by iterative root finding and explicitly addresses non-unique correspondences ([Chen et al., ICCV 2021](https://openaccess.thecvf.com/content/ICCV2021/papers/Chen_SNARF_Differentiable_Forward_Skinning_for_Animating_Non-Rigid_Neural_Implicit_Shapes_ICCV_2021_paper.pdf)). This is a warning that “warp in GPU” does not itself guarantee a cheap or single-valued mapping.

### Smallest discriminating experiment

1. **Fixture:** one analytic closed capsule-like character with two bones; add a second bent pose that approaches self-contact. Fix camera, light, material, render size, atlas/field resolution, and a deterministic 120-pose sequence from the repository benchmark conventions.
2. **Representations:** one canonical analytic SDF, then a voxelized copy of that SDF. Optionally add prebuilt Gaussian primitives for the same body as a separate adapter. Do not include learned reconstruction, general mesh import, or production asset authoring.
3. **Warp variants:** baseline conventional mesh skinning; a direct per-query inverse warp with known bound for SDF/voxel sampling; a separate bounded iterative inverse-skinning variant whose solve cost/failures are counted; and forward-transformed Gaussian centers with locally transformed shape. Keep all variants opt-in and separate from the default renderer.
4. **Correctness outputs:** silhouettes, actual surface depth, normals, warp Jacobian condition/determinant, inverse-solve count/failures, SDF bound violations, voxel sampling errors, Gaussian coverage and sorting artifacts. Preserve explicit miss/invalid/nonconverged statuses.
5. **Cost outputs:** per-pass GPU median/p95 across repeated matched runs, warp evaluation count, texture/primitive reads, memory, and CPU/update cost. A total FPS number cannot identify whether the warp, tracing, splat sort, or display path dominates.

These remain promotion requirements. The isolated analytic and two-bone probes below cover part of them; full-frame image, normal, voxel-warp and visually reviewed results remain open. Reuse the project’s [benchmark procedure and stop conditions](../2026-09-29/benchmark-protocol.md), freeze representation-specific thresholds before capture, and keep visual review separate from numeric summaries.

## Executed GPU feasibility probe (2026-10-03)

The probe is implemented in `src/probe.rs` with the compute kernel in `shaders/space_warp_sdf_probe.wgsl`; `scripts/in-nix mise run probe` records the result. It ray marches an analytic unit-sphere SDF through two known query-to-canonical fields and compares each 64-ray set with a CPU double-precision root search.

On Apple M1 Max / Metal, the sinusoidal shear `(x,y,z) -> (x,y,z + 0.2*sin(2.4*x))` used a global Lipschitz bound of `1.2683968`; all statuses matched, zero rays overshot the CPU root, max hit error was `0.000470879`, and p50/p95/max steps were `8/23/41`. The second field smoothly blends identity with one rigid inverse bone rotation over `x`, using a conservative `3.995003` Lipschitz bound restricted to query radius 10. Its 64 statuses also matched, it had zero step-bound violations, max hit error `0.000341691`, p50/p95/max steps `35/89/103`, and the minimum sampled Jacobian determinant was `0.109991` across the ray domain. This is a two-transform blend proxy, not inverse linear-blend skinning. Four combined 128-ray compute dispatches measured `0.029625`, `0.049625`, `0.056292`, and `0.055917 ms`; this tiny kernel timing is not comparable to DASHR rendering.

This first probe supports the lower-bound construction for the two analytic fields. Its bone case is a one-transform blend proxy and does not exercise spatially varying LBS weights. The follow-on probe below adds that inverse solve and a fixed pose sequence.

### Two-bone inverse-LBS feasibility probe (2026-10-03)

The new isolated kernel is in `shaders/inverse_lbs_sdf_probe.wgsl`; its CPU oracle, forward-skinned mesh baseline and wgpu dispatch are in `src/probe/inverse_lbs.rs`. `tests/gpu.rs::inverse_lbs_sdf_gpu_probe_matches_cpu_truth_across_fixed_pose_sequence` checks it on a native adapter, and `scripts/in-nix mise run probe` records it under `out/probe/capabilities.json`.

The fixture is a capsule SDF along the x axis, with radius `0.25` and center segment `[-0.75, 0.75]`. Bone 0 is identity; bone 1 rotates around y. Vertex and field weights use `w(x) = smoothstep(-1, 1, x)`, so the canonical-to-posed map is `F(x) = (1-w(x))x + w(x)R_y(theta)x`. The GPU solves `F(x)=p` with the analytic 3x3 Jacobian and Newton iteration, then evaluates the canonical capsule SDF. The sequence uses 120 deterministic poses `theta_i = 0.45 sin(2 pi i / 119)`, 32 orthographic rays per pose, a `1.02` world-space query bound, and a `1.1` canonical domain. CPU double-precision inverse solves, 512 ray samples and 40 bisection steps provide hit truth.

The traversal step uses a certified inverse lower-Lipschitz factor. On the radius-1.1 canonical domain, `||DF - I|| <= 2 sin(|theta|/2) * (1 + 0.75 * 1.1)`, using `||R_y(theta)-I|| = 2 sin(|theta|/2)` and `max ||grad w|| = 0.75`. Thus the safe sequence has a minimum lower bound of `0.1857315`. The minimum sampled GPU Jacobian determinant was `0.604091`; all 3,840 ray statuses matched the CPU oracle, the maximum hit-distance error was `0.000161648`, and no inverse solves or conservative steps failed. The step-violation comparison uses a `2e-4` object-distance tolerance. The 1,488-triangle forward-skinned mesh matched all ray hit statuses; its median and maximum depth differences from the analytic field were `0.0000994` and `0.0237153` object units.

On Apple M1 Max / Metal, two warm-up dispatches preceded ten measured dispatches. The GPU compute median/p95 were `0.318708/0.322209 ms`; each dispatch covered the 120-pose sequence plus its 32-ray stress pose. CPU root search took `104.46 ms`; forward-skinned mesh updates and ray tests took `32.64 ms`. These CPU/GPU workloads differ and do not establish a speedup or production frame time. The result JSON also records Newton work, maximum residual, trace steps and mesh depth errors.

A `theta = 2.4` rad near-contact pose estimates `0.043537` units between the transformed centerline endpoints after subtracting two capsule radii; its triangulated stress mesh reports zero self-intersection pairs. The certified lower-Lipschitz bound is negative (`-2.40194`), so the GPU returns `Invalid` for all 32 rays before attempting inversion. This proves fail-closed handling near contact, but not behavior on an actually intersecting mesh.

**Actual self-intersection stress pose (2026-10-03).** At `theta = π`, the endpoint-clearance estimate is `-0.5` object units and the posed 1,488-triangle mesh reports `341` intersecting triangle pairs. The inverse-Lipschitz lower bound is `-2.65`; all 32 GPU rays return `Invalid` before attempting inversion. This supplies an actual folded/self-overlapping mesh case to the probe and confirms the query-space method fails closed when its injectivity bound is unavailable. It does not validate surface quality through the fold, because no inverse solution is attempted there. The raw report is under `out/u20-self-contact/capabilities.json`.

U20 now has a measured spatially varying inverse-LBS prototype, fixed pose sequence, 32³/64³ voxel-field comparisons, and a π-radian pose with actual triangle self-intersections. Image-space silhouette review, normals, temporal voxel review, and integration into DASHR rendering remain open. No inverse-LBS or voxel-warp mode is exposed by the production library.

A companion CPU probe voxelized the same sphere SDF over `[-1.5,1.5]^3` at 16³, 32³ and 64³ float32 samples, then trilinearly sampled deterministic cell centers. Maximum/RMS sample errors were `0.173205/0.009381`, `0.083809/0.002178`, and `0.041239/0.000525`; grid payloads were 16 KiB, 128 KiB and 1 MiB. Subtracting `sqrt(3) * cell_spacing` gave zero sampled conservative-bound violations at each resolution, but that margin is wide enough to delay tracing and has not been measured on GPU. This is CPU feasibility data, not a renderer or voxel animation result. The Gaussian GPU adapter prototype above still needs a representative authored splat asset and visual review, and stays separate from the opaque-surface API.

### GPU dense-voxel warp follow-up (2026-10-03)

The U20 two-bone inverse-LBS map now also samples a `32³` float32 capsule SDF grid over `[-1.5,1.5]³`. Grid payload is `131,072` bytes and cell spacing is `0.096774`. The GPU samples the trilinear field and traces with `max(field_value, 0) / L` in canonical space, multiplied by the certified inverse-LBS lower bound. `L = 1.728675` is computed from the maximum x/y/z finite difference across every grid edge, combined as a Euclidean gradient bound; each within-cell partial derivative is a bilinear interpolation of those edge derivatives. The grid is not assumed to remain an exact SDF.

The CPU oracle separately root-searches the same trilinear field and the analytic capsule. On Apple M1 Max / Metal, the 120-pose × 32-ray sequence had zero status disagreement against either reference, zero inverse-solve failures and zero conservative-step violations within the `2e-4` comparison tolerance. Voxel-trace hit error against its CPU field root was at most `0.000243`; against the analytic surface the maximum/median error was `0.016367/0.004692` units. Trilinear interpolation error at 29,791 deterministic cell centers was max/RMS `0.068430/0.002764`. Trace steps were p50/p95/max `34/81/131`.

With ten warm-up and ten measured dispatches, GPU compute median/p95 were `0.353167/0.358750 ms` for 3,840 rays. CPU root work took `126.05 ms`. These are feasibility timings, not a matched renderer benchmark or speed claim. This established the bounded 32³ GPU voxel-warp probe; the separate 64³ numeric comparison follows below. Surface normals, full-frame silhouettes, temporal image review and voxel self-contact stress remain open.

### 64³ GPU voxel-warp resolution follow-up (2026-10-03)

The same inverse-LBS field, 120-pose sequence, 32 orthographic rays per pose, grid bounds, CPU root method, and conservative-step formula were run with a `64³` float32 capsule SDF. Grid payload increased from `131,072` bytes at 32³ to `1,048,576` bytes at 64³; spacing decreased from `0.096774` to `0.047619`. The independently measured trilinear Lipschitz bounds were `1.728675` and `1.731284` respectively.

The GPU 64³ run matched the voxel CPU root and analytic CPU status for all 3,840 rays, with zero inverse failures and conservative-step violations. Maximum hit-distance error against the voxel CPU root was `0.0001714`; against the analytic surface, maximum/median error was `0.003553/0.001078`, down from `0.016367/0.004692` at 32³. Trace steps were p50/p95/max `33/80/118` at 64³, compared with `34/81/131` at 32³. Trilinear sample-center maximum/RMS error fell from `0.068430/0.002764` to `0.033672/0.000683` over `250,047` samples.

With ten warm-up and ten measured dispatches, one release run measured GPU median/p95 `0.350917/0.353542 ms` at 32³ and `0.326625/0.640917 ms` at 64³; three 64³ samples were `0.638–0.641 ms` and seven were `0.322–0.327 ms`. A repeat measured `0.349625/0.351250 ms` and `0.321125/0.326000 ms` respectively. Treat this as timing variability, not a speedup claim. CPU oracle times were `125.13/125.27 ms` in the first run because the inverse/root sample sequence is the same. This closes the numeric resolution-comparison gate for these two grids only. No full-frame silhouette, normal, temporal, or visual review was performed; those gates remain open.

### Promotion gates and common failure modes

- **Mapping validity:** a global implicit/voxel field has no natural DASHR chart seam or teleport. Reusing chart transforms is a test of that wrapper, not proof the representation has solved seam transport. At folds or near-self-contact, a posed point may map to multiple canonical points; report ambiguity rather than selecting an arbitrary root. This follows from the mapping issue identified in SNARF and is a project-level acceptance inference.
- **Safe traversal:** retain a conservative bound after every warp and resolution conversion. If the bound is unknown or violated, stop that variant; do not mask it with a larger step budget.
- **Normals and depth:** derive normals from the same field used for hits, and compare actual hit depth rather than shell depth. Gaussian output needs separately documented compositing/depth semantics.
- **Temporal stability:** inspect the full fixed pose sequence for holes, pops, fold changes, oscillating normals, and splat sorting changes. A static image does not establish animation suitability.
- **Scope:** no candidate becomes a default library dependency or asset-schema promise from this research. Promotion requires a concrete consumer, a stable representation contract, the correctness gates above, and separately reviewed performance evidence.

## Source notes

- Hart’s [sphere-tracing paper](https://doi.org/10.1007/s003710050084) supports the conservative distance-bound basis for SDF stepping.
- Hart, Sandin, and Kauffman’s [deterministic 3D fractal paper](https://www2.evl.uic.edu/documents/raytracing3d.pdf) supports ray tracing selected fractal families using an unbounding-volume construction.
- Kerbl et al.’s [3D Gaussian Splatting paper](https://arxiv.org/abs/2308.04079) supports anisotropic Gaussian radiance primitives and visibility-aware splatting.
- Crassin et al.’s [GigaVoxels paper](https://www-sop.inria.fr/reves/Basilic/2009/CNLE09/CNLE09.pdf) supports octree/brick voxel rendering and documents animation as a major open issue.
- Pumarola et al.’s [D-NeRF paper](https://openaccess.thecvf.com/content/CVPR2021/papers/Pumarola_D-NeRF_Neural_Radiance_Fields_for_Dynamic_Scenes_CVPR_2021_paper.pdf) supports canonical/deformed-space modeling for dynamic scenes.
- Chen et al.’s [SNARF paper](https://openaccess.thecvf.com/content/ICCV2021/papers/Chen_SNARF_Differentiable_Forward_Skinning_for_Animating_Non-Rigid_Neural_Implicit_Shapes_ICCV_2021_paper.pdf) supports the need to handle inverse/forward skinning and non-unique correspondences for implicit shapes.
